# Use Cases - Кассовая система

Данный документ описывает функциональные требования системы в виде use cases (вариантов использования).

## Актёры системы

### 1. Администратор (Admin)
Сотрудник с полными правами доступа, отвечающий за управление системой, товарами и пользователями.

**Права доступа:**
- Управление товарами (добавление, удаление)
- Управление пользователями (регистрация, удаление)
- Просмотр и экспорт отчётов о продажах
- Очистка истории продаж
- Проведение продаж (как кассир)

### 2. Кассир (Cashier)
Сотрудник, работающий на кассе и проводящий продажи товаров.

**Права доступа:**
- Проведение продаж
- Просмотр списка товаров
- Поиск товаров по артикулу

## Use Case 1: Авторизация в системе

**ID:** UC-001  
**Название:** Авторизация в системе  
**Актёр:** Администратор, Кассир  
**Описание:** Пользователь входит в систему с использованием логина и пароля.

### Предусловия:
- Пользователь зарегистрирован в системе
- Пользователь не авторизован

### Основной поток:
1. Пользователь открывает страницу авторизации
2. Система отображает форму входа
3. Пользователь вводит логин и пароль
4. Пользователь нажимает кнопку "Войти"
5. Система проверяет учётные данные
6. Система создаёт сессию пользователя
7. Система перенаправляет пользователя на соответствующую страницу:
   - Администратора → на страницу управления (AdminPage)
   - Кассира → на страницу кассы (CashierPage)

### Альтернативные потоки:
**5a. Неверные учётные данные:**
1. Система отображает сообщение об ошибке "Неверный логин или пароль"
2. Пользователь остаётся на странице авторизации
3. Возврат к шагу 3 основного потока

**5b. Ошибка соединения с сервером:**
1. Система отображает сообщение "Ошибка соединения с сервером"
2. Пользователь может повторить попытку

### Постусловия:
- Пользователь авторизован в системе
- Создана сессия с временем жизни 1 час

## Use Case 2: Управление товарами

**ID:** UC-002  
**Название:** Управление товарами  
**Актёр:** Администратор  
**Описание:** Администратор добавляет новые товары в систему или удаляет существующие.

### Предусловия:
- Пользователь авторизован как администратор
- Пользователь находится на странице управления

### Основной поток (Добавление товара):
1. Администратор нажимает кнопку "Добавить товар"
2. Система отображает модальное окно с формой добавления
3. Администратор заполняет поля:
   - Артикул (уникальный идентификатор)
   - Название товара
   - Цена (число с 2 знаками после запятой)
   - Количество (целое число)
4. Администратор нажимает кнопку "Добавить"
5. Система проверяет данные:
   - Все поля заполнены
   - Артикул уникален
   - Цена > 0
   - Количество >= 0
6. Система сохраняет товар в базу данных
7. Система закрывает модальное окно
8. Система обновляет список товаров

### Альтернативные потоки:
**5a. Артикул уже существует:**
1. Система отображает ошибку "Товар с таким артикулом уже существует"
2. Пользователь остаётся в модальном окне
3. Возврат к шагу 3

**5b. Некорректные данные:**
1. Система отображает ошибку с описанием проблемы
2. Возврат к шагу 3

**5c. Ошибка доступа (недостаточно прав):**
1. Система отображает "Доступ запрещён"
2. Операция отменяется

### Основной поток (Удаление товара):
1. Администратор находит товар в списке
2. Администратор нажимает кнопку удаления (иконка корзины)
3. Система запрашивает подтверждение удаления
4. Администратор подтверждает действие
5. Система удаляет товар из базы данных
6. Система обновляет список товаров

### Альтернативные потоки:
**4a. Отмена удаления:**
1. Администратор отменяет действие в диалоге подтверждения
2. Товар не удаляется
3. Возврат к списку товаров

### Постусловия:
- При добавлении: Новый товар присутствует в базе данных и отображается в списке
- При удалении: Товар удалён из базы данных и не отображается в списке

7. Система создаёт нового пользователя в базе данных

3. Система проверяет, что удаляемый пользователь не является текущим

6. Система удаляет пользователя из базы данных

### Альтернативные потоки:

2. Операция отменяется

**5a. Отмена удаления:**
1. Администратор отменяет действие в диалоге подтверждения
2. Пользователь не удаляется
3. Возврат к списку пользователей

### Постусловия:
- При регистрации: Новый пользователь создан и отображается в списке
- При удалении: Пользователь удалён из базы и не отображается в списке

## Use Case 4: Проведение продажи

**ID:** UC-004  
**Название:** Проведение продажи  
**Актёр:** Кассир, Администратор  
**Описание:** Пользователь формирует корзину товаров и проводит оплату.

### Предусловия:
- Пользователь авторизован (кассир или администратор)
- Пользователь находится на странице кассы
- В базе данных есть товары с количеством > 0

### Основной поток:
1. Кассир вводит артикул товара в поле поиска
2. Система ищет товар по артикулу
3. Система отображает найденный товар с информацией:
   - Название
   - Цена
   - Доступное количество
4. Кассир вводит количество товара для покупки
5. Кассир нажимает кнопку "Добавить в корзину"
6. Система проверяет доступность товара
7. Система добавляет товар в корзину
8. Система отображает корзину с добавленными товарами и общей суммой
9. Кассир повторяет шаги 1-8 для добавления других товаров (опционально)
10. Кассир нажимает кнопку "Оплатить"
11. Система проверяет наличие товаров в корзине
12. Система отправляет запрос на проведение продажи
13. Система:
    - Списывает количество товаров со склада
    - Сохраняет записи о продаже в таблицу sold_products
    - Фиксирует дату и время продажи
14. Система отображает сообщение об успешной продаже с общей суммой
15. Система очищает корзину

### Альтернативные потоки:
**2a. Товар не найден:**
1. Система отображает сообщение "Товар не найден"
2. Возврат к шагу 1

**6a. Недостаточное количество товара:**
1. Система отображает ошибку "Недостаточно товара на складе"
2. Товар не добавляется в корзину
3. Возврат к шагу 1

**11a. Корзина пуста:**
1. Система отображает сообщение "Корзина пуста"
2. Оплата не производится

**13a. Товар закончился между добавлением в корзину и оплатой:**
1. Система откатывает транзакцию
2. Система отображает ошибку с указанием проблемного товара
3. Кассир должен обновить корзину
4. Возврат к шагу 9

**13b. Ошибка соединения с сервером:**
1. Система отображает ошибку "Ошибка соединения"
2. Корзина сохраняется
3. Кассир может повторить попытку оплаты

### Дополнительные действия:
**Удаление товара из корзины:**
1. Кассир нажимает кнопку удаления рядом с товаром в корзине
2. Система удаляет товар из корзины
3. Система пересчитывает общую сумму

### Постусловия:
- Продажа зафиксирована в базе данных (таблица sold_products)
- Количество проданных товаров списано со склада (таблица products)
- Корзина очищена
- Кассир может начать новую продажу

## Use Case 5: Просмотр и экспорт отчёта о продажах

**ID:** UC-005  
**Название:** Просмотр и экспорт отчёта о продажах  
**Актёр:** Администратор  
**Описание:** Администратор просматривает агрегированный отчёт о продажах и экспортирует его в CSV.

### Предусловия:
- Пользователь авторизован как администратор
- Пользователь находится на странице управления
- В системе есть история продаж (таблица sold_products)

### Основной поток:
1. Администратор нажимает кнопку "Экспортировать отчёт"
2. Система формирует запрос к базе данных с агрегацией:
   - Группировка по артикулу товара
   - Суммирование количества проданных единиц
   - Суммирование выручки по каждому товару
   - Расчёт общей выручки
3. Система получает данные отчёта
4. Система формирует CSV-файл с кодировкой UTF-8 (с BOM для Excel):
   - Заголовки: Артикул, Название, Количество, Выручка
   - Строки с данными для каждого товара
   - Итоговая строка с общей выручкой
5. Система инициирует скачивание файла `sales_report_[дата-время].csv`
6. Браузер сохраняет файл в папку загрузок пользователя

### Альтернативные потоки:
**3a. Нет данных о продажах:**
1. Система создаёт пустой CSV с только заголовками
2. Общая выручка = 0
3. Файл всё равно загружается

**3b. Ошибка соединения с сервером:**
1. Система отображает ошибку "Не удалось получить данные"
2. Файл не создаётся

**5a. Браузер блокирует скачивание:**
1. Пользователь разрешает скачивание в браузере
2. Файл загружается

### Постусловия:
- CSV-файл сохранён на компьютере администратора
- Файл содержит актуальные данные на момент экспорта
- Файл корректно открывается в Excel с отображением кириллицы

## Use Case 6: Очистка истории продаж

**ID:** UC-006  
**Название:** Очистка истории продаж  
**Актёр:** Администратор  
**Описание:** Администратор удаляет всю историю продаж из системы.

### Предусловия:
- Пользователь авторизован как администратор
- Пользователь находится на странице управления

### Основной поток:
1. Администратор нажимает кнопку "Очистить отчёт"
2. Система отображает диалог подтверждения:
   - Текст: "Вы уверены, что хотите очистить всю историю продаж?"
   - Кнопки: "Да", "Отмена"
3. Администратор нажимает "Да"
4. Система отправляет запрос на удаление всех записей из таблицы sold_products
5. Система удаляет все записи
6. Система отображает сообщение "История продаж очищена"

### Альтернативные потоки:
**3a. Отмена операции:**
1. Администратор нажимает "Отмена"
2. Диалог закрывается
3. История продаж не изменяется

**5a. Ошибка доступа:**
1. Система отображает ошибку "Доступ запрещён"
2. История не очищается

**5b. Ошибка соединения:**
1. Система отображает ошибку "Ошибка соединения"
2. История не очищается
3. Администратор может повторить попытку

### Постусловия:
- Таблица sold_products пуста
- Последующие экспорты отчётов будут содержать нулевую выручку
- Данные о товарах (products) и пользователях (users) не затронуты

## Use Case 7: Выход из системы

**ID:** UC-007  
**Название:** Выход из системы  
**Актёр:** Администратор, Кассир  
**Описание:** Пользователь завершает сеанс работы в системе.

### Предусловия:
- Пользователь авторизован в системе

### Основной поток:
1. Пользователь нажимает кнопку "Выход"
2. Система отправляет запрос на завершение сессии
3. Система удаляет серверную сессию пользователя
4. Система удаляет cookie сессии
5. Система перенаправляет пользователя на страницу авторизации

### Альтернативные потоки:
**3a. Ошибка соединения:**
1. Система удаляет локальные данные сессии
2. Пользователь перенаправляется на страницу авторизации
3. Серверная сессия истечёт автоматически через 1 час

### Постусловия:
- Пользователь не авторизован
- Сессия удалена
- Доступ к защищённым страницам запрещён

## Бизнес-правила

### BR-001: Уровень изоляции транзакций
Все операции изменения данных (добавление товаров, продажа) используют уровень изоляции `SERIALIZABLE` для предотвращения race conditions.

### BR-002: Блокировка при продаже
При проведении продажи используется блокировка на уровне строк (`with_for_update()`) для предотвращения одновременного списания одного товара.

### BR-003: Отрицательное количество
Система не допускает отрицательного количества товара на складе. Продажа автоматически блокируется, если запрошенное количество превышает доступное.

### BR-004: Защита от самоудаления
Администратор не может удалить свою собственную учётную запись.

### BR-005: Время жизни сессии
Сессия пользователя действительна в течение 1 часа (3600 секунд) с момента входа.

### BR-006: Агрегация отчёта
Отчёт о продажах агрегирует данные по артикулу товара:
- Суммируется общее количество проданных единиц
- Суммируется общая выручка
- Рассчитывается итоговая выручка по всем товарам

### BR-007: История продаж
Каждая продажа сохраняется в таблице sold_products с фиксацией:
- Артикула и названия товара на момент продажи
- Цены на момент продажи
- Количества
- Суммы по позиции
- Даты и времени продажи

## Нефункциональные требования

### NFR-001: Производительность
- Время отклика на запросы API: не более 500 мс
- Поддержка одновременной работы до 10 пользователей

### NFR-002: Надёжность
- Использование транзакций для обеспечения целостности данных
- Автоматический rollback при ошибках

### NFR-003: Безопасность
- Хеширование паролей с использованием Werkzeug
- Сессионная аутентификация с HttpOnly cookies
- Разграничение прав доступа (admin/cashier)

### NFR-004: Юзабилити
- Интуитивный интерфейс на русском языке
- Подтверждение критических операций (удаление, очистка истории)
- Информативные сообщения об ошибках

### NFR-005: Совместимость
- Поддержка современных браузеров (Chrome, Firefox, Edge)
- Корректное отображение кириллицы в CSV-экспорте (UTF-8 BOM)
